# Debugging MariaDB Issues

There is a critical issue with the Nautilus application in Stratos DC: it cannot connect to its database because MariaDB is down on the database server. The service configuration points to the wrong data directory, so correct the configuration, permissions, and socket location before starting the service.

## Steps

1. Connect to the database server and inspect the MariaDB log.

    ```sh
    ssh peter@stdb01
    sudo tail -f /var/log/mariadb/mariadb.log
    ```

    On systems where the log is written directly under `/var/log`, use:

    ```sh
    sudo tail -f /var/log/mariadb.log
    ```

2. Check the service status and the systemd journal.

    ```sh
    sudo systemctl status mariadb
    sudo journalctl -u mariadb -n 50 --no-pager
    ```

    The service is inactive and fails to start because its configured data directory is `/var/lib/mysql`, while the database files are stored in `/var/lib/mysqld`.

3. Find the MariaDB server configuration file that defines the data directory, then update it.

    ```sh
    sudo grep -RIn --include='*.cnf' '^[[:space:]]*\(datadir\|socket\)' /etc/my.cnf /etc/my.cnf.d 2>/dev/null
    sudo vi /etc/my.cnf.d/mariadb-server.cnf
    ```

    Use the configuration file returned by `grep` if it differs from the example above. In the `[mariadb]` or `[mysqld]` section, ensure these settings reference the actual location:

    ```ini
    datadir=/var/lib/mysqld
    socket=/var/lib/mysqld/mysql.sock
    ```

    `ib_buffer_pool` is a buffer-pool dump file kept in the data directory. If it is still in the old directory, move it with the database files; do not edit its contents.

    ```sh
    sudo test -f /var/lib/mysql/ib_buffer_pool && sudo mv /var/lib/mysql/ib_buffer_pool /var/lib/mysqld/ib_buffer_pool
    ```

4. Correct the data-directory ownership and permissions. The MariaDB process must be able to read and write the directory and create its socket there.

    ```sh
    sudo chown -R mysql:mysql /var/lib/mysqld
    sudo chmod 755 /var/lib/mysqld
    ```

5. Enable the service at boot, restart it, and verify that the database accepts connections.

    ```sh
    sudo systemctl enable mariadb
    sudo systemctl restart mariadb
    sudo systemctl is-active mariadb
    sudo mariadb-admin ping
    sudo mariadb -e 'SELECT VERSION();'
    ```

## Good to Know?

### MariaDB Troubleshooting

- **Log files**: `/var/log/mariadb/mariadb.log` and `/var/log/mysqld.log`
- **Configuration**: `/etc/my.cnf` and `/etc/my.cnf.d/`
- **Data directory**: commonly `/var/lib/mysql/`, but always verify the configured location
- **Socket file**: commonly `/var/lib/mysql/mysql.sock`; it must match the configured data directory

### Common Issues

- **Permission problems**: the data directory should be owned by `mysql:mysql` and writable by MariaDB.
- **Configuration errors**: verify the option syntax and that `datadir` and `socket` point to real locations.
- **Disk space**: make sure the data and log volumes have enough free space.
- **Port conflicts**: check whether another process is using the default MariaDB port, `3306`.

### Diagnostic Commands

- `systemctl status mariadb` checks the service state.
- `journalctl -u mariadb` shows MariaDB's systemd log entries.
- `mariadb-admin ping` tests whether the server is responding.
- `mariadb -u root -p` tests an authenticated database connection.
